# Plan 01-02: Tick Loop + Diff Computation + Console Logging + Integration

Depends on Plan 01-01 (types, rules engine, Board constructor). Adds diff computation to Board, setTimeout-chaining game loop in Game orchestrator, console logging, and wires into `src/index.ts`. Completion means server starts and logs `[tick N] X changes | (x,y:status)...` to console each tick.

Tracer completes when integration task (Task 5) runs: `bun --hot src/index.ts` starts, console shows tick 1 with diff output, tick counter increments.

## must_haves

1. `Board.tick()` computes diff between old/new grid, returns `TickResult` with correct `tick`, `timestamp`, and `changes`
2. Empty diff (no changes) still returns `TickResult` with `changes: []` and incremented tick counter
3. `Game.start()` schedules first tick via `setTimeout`, chains subsequent ticks
4. `Game.stop()` calls `clearTimeout`, transitions state to `"stopped"`
5. Double `start()` is idempotent — does not create parallel timers
6. Console log format: `[tick N] X changes | (x,y:0|1) ...` with preview of first 5 changes
7. `src/index.ts` imports `Game`, creates instance, calls `game.start()`
8. All tests pass: `bun test src/game/`

## Security Domain

Same posture as Plan 01-01 — **zero attack surface**. No network I/O, no user input, no external dependencies. `setTimeout` chaining is bounded to one active timer per Game instance. Console logging is intentional and contains no secrets. No security mitigations required.

## Tasks

### Task 2: Diff computation in Board.tick()

<action>
Add `tick()` method to `src/game/board.ts`:
1. Call `computeNextGeneration(this.grid, this.width, this.height)` to get `nextGrid`
2. Iterate `this.grid` by index, compare `this.grid[i] !== nextGrid[i]`
3. For each mismatch, push `{ x: i % this.width, y: Math.floor(i / this.width), alive: nextGrid[i] === 1 }` into `changes: CellChange[]`
4. Assign `this.grid = nextGrid`
5. Increment `this.tickCount`
6. Return `{ tick: this.tickCount, timestamp: Date.now(), changes }`

Add tests to `src/game/board.test.ts`:
- Set up board with empty grid, run `tick()`, assert `changes.length === 0`, `tickCount === 1`
- Set up board with single alive cell at center (no neighbors) — cell dies after tick, assert `changes.length === 1`, change has `alive: false`
- Set up board with 2x2 block pattern — after tick, assert `changes.length === 0` (stable) despite tick incrementing
- Assert `TickResult.timestamp` is a number > 0
- Assert `tickCount` increments: 2x tick → count === 2
</action>

<acceptance_criteria>
[SC-3] Board with 2x2 block produces `changes: []` after tick, `tickCount === 1`
[SC-2] Board with single center cell produces 1 change (cell dies), `alive: false`
[SC-1] Board.tick() returns `TickResult` with `tick`, `timestamp`, `changes` array — all populated

### Task 3: Game orchestrator with setTimeout chaining

<action>
Create `src/game/game.ts`:
- Import `Board` from `./board`
- Import `GameState`, `TickResult` from `./types`
- Export `Game` class:
  - Constructor: takes optional `interval: number` (default 1000), creates `Board` with `{ width: 100, height: 100, initialFill: "random" }`, sets `state = "idle"`
  - `start()`: if `state === "running"` return (idempotent guard). Set `state = "running"`. Call `this.scheduleTick()`
  - `stop()`: if `timerId != null`, `clearTimeout(timerId)`, set `timerId = null`. Set `state = "stopped"`
  - Private `scheduleTick()`: assign `this.timerId = setTimeout(() => { const result = this.board.tick(); console.log(formatTickLog(result)); if (this.state === "running") this.scheduleTick() }, this.interval)`
- Export `formatTickLog(result: TickResult): string`:
  - Count `changedCount = result.changes.length`
  - Preview first 5 changes as `(x,y:0|1)` joined by space
  - Suffix with `... +N more` if >5
  - Return `` `[tick ${result.tick}] ${changedCount} changes | ${preview}${suffix}` ``

Create `src/game/game.test.ts`:
- Test `start()` transitions state to `"running"`
- Test `stop()` transitions state to `"stopped"` (start then stop immediately)
- Test double `start()` is idempotent — second call does not create second timer (state stays "running")
- Test `Game` constructor creates Board with 100x100 random fill
- Test tick fires within interval window — start game, await ~50ms, check `tickCount > 0`, stop game (loose assertion due to timer jitter)
</action>

<acceptance_criteria>
[SC-3] After `game.stop()`, state is `"stopped"`, no further ticks fire
[SC-2] Double `game.start()` keeps state `"running"`, does not create parallel timers
[SC-1] `game.start()` transitions state to `"running"`, schedules first tick via `setTimeout`
</acceptance_criteria>
